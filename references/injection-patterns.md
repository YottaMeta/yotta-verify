# 提示注入（Prompt Injection）检测模式

元信对技能 / 包文本做 8 类提示注入检测（scripts/verify_rules.py 中 PIJ-001 ~ PIJ-028）。
命中判定为启发式：置信度 + 人工确认。安全教学类技能的自描述命中属「描述注入手法」而非注入
本身，请结合命中位置（文件 + 行号）人工判断。

> 本文档为教学用途，示例一律脱敏（用「类」表述），不给完整可复制注入串。

## 1. 指令覆盖 / 优先级操纵（PIJ-001 ~ PIJ-004）

要求智能体忽略前序指令 / 设定，或覆盖安全护栏。典型形态：

- ignore-previous-instructions 类英文指令（忽略前序指令 / 上下文）
- disregard-earlier-rules 类（无视前序规则）
- from-now-on 重定向类（从现在起只听注入者）
- override-guardrails 类（覆盖安全护栏）

风险：让智能体脱离宿主设定，执行注入者意图。

## 2. 角色伪造 / 权限升级（PIJ-005 ~ PIJ-008）

伪装成系统 / 管理员 / 开发者角色，或暗示以全权执行。典型形态：

- you-are-now-developer-mode 类（伪装开发者模式）
- act-as-system-admin 类（扮演系统管理员）
- with-full-root-privileges 类（以 root 全权）

风险：绕过权限边界执行越权操作。

## 3. 隐藏 / 编码指令（PIJ-009 ~ PIJ-010 + PIJ-B64）

把指令伪装成系统消息，或用编码传递。典型形态：

- 伪系统消息类（在文本中宣称「以下是系统指令」，引导宿主按系统级执行）
- base64 / 十六进制编码的 shell 命令串（解码后含下载 / 执行类命令词）

风险：绕过文本审查传递可执行指令。

## 4. 数据外传指令（PIJ-011 ~ PIJ-013）

要求把上下文 / 记忆 / 环境变量 / 密钥传往远端地址。典型形态：

- send-memory-and-env-to-url 类（把记忆与 .env 发往某地址）
- 中文外传类（把上下文 / 环境变量 / 密钥「传往」某处）
- 读取 .env 后外传类（先读再传）

风险：技能安装后窃取宿主上下文与凭据（供应链数据泄露）。

## 5. 分隔符逃逸 / 伪系统标签（PIJ-014 ~ PIJ-017）

用 system 标签伪装系统指令，或设置条件触发。典型形态：

- system 标签类（在文本中用系统标签包裹指令）
- reveal-system-prompt 类（要求泄露宿主系统提示词）
- when-say-then-do 类（条件注入：用户说特定词即执行）

风险：伪装高优先级指令，或埋设触发条件。

## 6. 工具自执行指令（PIJ-018 ~ PIJ-020）

要求智能体自动执行下载 / 命令。典型形态：

- run-following-command 类（要求执行注入者给的命令）
- download-and-execute 类（下载后执行）

风险：装后自动执行远程代码（结合 DEX 类规则为 critical）。

## 7. 越权 / 隐藏意图（PIJ-021 ~ PIJ-026）

要求不告知用户、只回复确认词、不经同意直接执行。典型形态：

- don't-tell-the-user 类英文指令（隐藏行为）
- 中文隐藏类（「不告知用户」类表述）
- reply-ok-only 类（只回复确认词）
- 不经同意直接执行类（无需征得用户同意）

风险：隐藏真实行为，规避人类监督。

## 8. 凭据 / 输入采集（PIJ-027 ~ PIJ-028）

要求记录用户键入 / 键盘 / 凭据。典型形态：

- keystroke-capture 类英文指令（键盘键入采集）
- 中文采集类（「记录用户键入」类表述）

风险：安装后窃取用户键入与凭据。

## 人工确认建议

- 命中位于 SKILL.md 的教学 / 防御语境（含「检测」「防」「识别」等词）时，多为自描述，非注入；
- 命中位于脚本注释 / 非执行文本时风险较低；命中位于可执行路径且为「指令性」文本时风险高；
- verdict 仅供人工决策参考，最终判断由用户。
